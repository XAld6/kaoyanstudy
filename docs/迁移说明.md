# 迁移说明：localStorage → 服务端

本文记录把旧版「浏览器 localStorage」里的考研学习数据搬上 VPS 服务端的一 次性步骤，供新环境或重装时参考。

## 背景

- 旧版（改造前）：学习数据全部存在浏览器 `localStorage`（键 `kaoyan-study-console:v1`，专注统计 `kaoyan-study-console:focus-stats:v1`）。
- 新版：数据以服务端 SQLite 为唯一数据源；浏览器只保留只读缓存。**旧键全程只读，永远不会被程序写入或删除**，所以迁移不丢数据、可重试。

## 方式一：一键迁移（推荐，无需文件）

在**存有旧数据的那个浏览器**里打开线上地址（或本机开发地址）：

1. 进入「设置」页；
2. 点 **「从本机旧数据一键迁移」**；
3. 状态栏提示「已把本机旧数据迁移到服务器（revision N）」，迁移完成。

说明：

- 等价于「恢复备份」语义（整体替换服务器当前内容），幂等可重试；
- 服务器上的旧内容不会丢——导入前会自动落一份 `backups/pre-import-<时间>.db` 数据库快照；
- 迁移完成后旧 localStorage 数据仍保留在本机浏览器里，可随时再次迁移。

## 方式二：导出文件导入（跨浏览器/换电脑）

1. 在旧浏览器打开旧版应用（或新版任意页面），设置页 **「导出 JSON 备份」**，得到一个 `kaoyan-study-<日期>.json` 文件；
2. 在新浏览器打开线上地址，设置页点 **「导入 JSON 到服务器」**，选择该文件；
3. 导入前系统会自动下载一份当前服务器数据备份（`kaoyan-study-backup-before-import-<日期>.json`）。

## 方式三：服务器整机恢复（服务器离线时）

服务器每日 03:17 自动备份双份：

- `app-<时间>.db.gz`（SQLite 一致快照，整机恢复用）：
  ```bash
  gunzip -c /opt/kaoyan-console/backups/app-<时间>.db.gz > /tmp/app-restore.db
  sudo -u kaoyan sqlite3 /opt/kaoyan-console/data/app.db ".restore '/tmp/app-restore.db'"
  sudo systemctl restart kaoyan-api
  ```
- `app-<时间>.json.gz`（网页可直接读回）：
  解压后在任意浏览器设置页「导入 JSON 到服务器」上传即可。

## 常见问题

- **导入后是示例数据？** 说明服务器是空库、页面刚刚播种了默认示例数据；此时再做一次迁移/导入（replace 语义整体覆盖）即可。
- **迁移/导入做了两次会重复吗？** 不会。replace 为整体替换、merge 按 id/date 幂等合并，重复执行结果一致。
- **迁移后能删掉旧 localStorage 吗？** 旧键由程序保留（不写不删），建议确认服务器数据无误后，再手动清浏览器站点数据。
