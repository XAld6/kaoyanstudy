# 十堰运维札记：设计规格

日期：2026-07-31

## 1. 目标

建设一个面向中文读者的技术实践博客，记录 VPS、NAT 主机、国内网络线路、部署排障和小型服务实践。博客必须能在当前 2 核、约 2GB 内存、NAT IPv4、无 IPv6 的 VPS 上稳定运行，并支持通过浏览器后台维护文章。

第一版的成功标准是：访客可以在移动端和桌面端顺畅浏览文章；管理员可以登录后台完成文章的创建、编辑、发布、撤回和删除；系统不依赖 Docker Hub 或大型外部服务；数据库和上传文件可以独立备份。

## 2. 方案决策

采用轻量定制方案：`Nginx + FastAPI + SQLite`。

- Nginx 负责公网 HTTP、静态资源和反向代理。
- FastAPI 只监听 `127.0.0.1:8000`，处理后台、文章 API、Markdown 渲染和认证。
- SQLite 保存文章、标签、管理员会话和媒体元数据。
- 上传图片保存在应用数据目录，不依赖对象存储。
- systemd 管理应用进程，服务商将公网 Web 端口映射到 VPS 的 `80` 端口；SSH 继续使用现有映射。

不采用 WordPress 或 Ghost：它们的插件、数据库、容器和海外依赖对这台 NAT 主机的资源与线路不划算，也会扩大公网攻击面。

## 3. 用户体验

### 公共前台

- 首页展示站名“十堰运维札记”、署名“一名在折腾 VPS 的人”、一篇置顶文章和最新文章列表。
- 采用已确认的“野外笔记”方向：图文并置、轻微地点感、纸面背景、青绿色与珊瑚色点缀，信息密度适中。
- 导航包含首页、文章、标签、关于；移动端导航折叠为图标按钮。
- 首页展示真实的文章数量、最近更新时间和标签，不制作虚假的业务指标。
- 文章页包含标题、摘要、发布日期、标签、封面、正文、目录和上一篇/下一篇导航。
- Markdown 支持标题、列表、引用、代码块、表格、链接和图片；代码块提供复制按钮。
- 搜索按标题、摘要、正文和标签匹配，结果为空时显示明确状态。
- 第一版不开放公开评论，减少垃圾内容、验证码和邮件通知等维护成本。

### 管理后台

- `/admin/login` 提供管理员登录。
- `/admin` 展示文章总数、草稿数、最近编辑记录和快速新建入口。
- 文章列表支持按状态、标签和关键词筛选。
- 编辑器支持标题、摘要、正文 Markdown、标签、封面、slug、草稿/已发布状态和发布时间。
- 编辑页面提供编辑/预览切换，预览结果与公共文章页使用同一套 Markdown 渲染规则。
- 删除文章需要二次确认；已发布文章删除后不应留下可访问的旧路由。
- 媒体区支持上传、预览、复制图片路径和删除未使用图片。
- 第一版只支持一个管理员账号；管理员密码只保存为强哈希，登录会话使用随机 token，并支持退出登录。

## 4. 视觉系统

### 视觉语言

采用“野外笔记”而不是传统运维面板：页面像一册持续更新的线路与服务观察记录。首页主视觉使用本地位图封面，不能依赖 Unsplash 等海外资源。

### 色彩

- 纸面背景：`#F5F3EC`
- 墨色正文：`#203034`
- 青绿色主色：`#2E6266`
- 珊瑚色强调：`#D87355`
- 暖黄色提示：`#D8A75D`
- 线条和次要文字：`#CBD3CC`、`#667477`

页面使用实色和真实图片，不用大面积渐变、装饰性光球或悬浮卡片堆叠。重复文章项可以使用轻边框卡片，圆角不超过 8px。标题和正文保持稳定的中文字号，不随视口缩放字体。

### 响应式

- 桌面端内容最大宽度约 1180px，首页使用主文章与侧栏的非对称布局。
- 移动端改为单列，主视觉图片保持固定比例，正文行长控制在舒适范围。
- 所有按钮、输入框和编辑区域保持稳定高度，避免动态文本导致布局跳动。
- 颜色对比满足可读性；键盘焦点、错误提示和空状态清晰可见。

## 5. 数据与接口

### 数据表

- `users`: `id`, `username`, `password_hash`, `created_at`, `updated_at`
- `sessions`: `id`, `user_id`, `token_hash`, `expires_at`, `created_at`
- `posts`: `id`, `slug`, `title`, `summary`, `content_markdown`, `content_html`, `cover_path`, `status`, `published_at`, `created_at`, `updated_at`
- `tags`: `id`, `name`, `slug`
- `post_tags`: `post_id`, `tag_id`
- `media`: `id`, `path`, `mime_type`, `size`, `created_at`

`slug` 唯一且只允许小写字母、数字和连字符。公开页面使用 `/posts/<slug>`，后台编辑使用稳定的数值 ID。

### API 边界

- `POST /api/auth/login`: 登录并设置 HttpOnly、SameSite=Lax 会话 cookie。
- `POST /api/auth/logout`: 撤销当前会话。
- `GET /api/me`: 返回当前登录状态。
- `GET /api/posts`: 公共文章分页、搜索和标签筛选。
- `GET /api/posts/<slug>`: 返回已发布文章。
- `GET /api/admin/posts`: 管理员文章列表。
- `POST /api/admin/posts`: 新建文章。
- `PUT /api/admin/posts/<id>`: 更新文章。
- `DELETE /api/admin/posts/<id>`: 删除文章。
- `POST /api/admin/media`: 上传媒体。
- `DELETE /api/admin/media/<id>`: 删除媒体。

所有写接口必须验证会话、输入长度、slug 唯一性和 CSRF token。Markdown HTML 必须经过允许列表清洗，禁止任意脚本、事件属性和危险 URL。

## 6. 部署与运维

应用目录规划为：

```text
/opt/shiyan-blog/app
/opt/shiyan-blog/data/blog.db
/opt/shiyan-blog/uploads
/opt/shiyan-blog/backups
/etc/shiyan-blog/blog.env
/etc/systemd/system/shiyan-blog.service
/etc/nginx/sites-available/shiyan-blog
```

- 应用用户不使用 root 运行；目录按最小权限设置。
- `blog.env` 保存随机会话密钥和管理员初始化参数，不进入代码仓库。
- Nginx 只代理到本机 FastAPI，并设置上传大小、静态缓存和安全响应头。
- SQLite 使用 WAL 模式；每天保留一份数据库和媒体索引备份，保留最近 7 份。
- 第一版使用 HTTP 验证功能；有域名和 80/443 映射后，再申请 HTTPS 证书。国内公开域名部署需自行确认 ICP 备案要求。
- 不自动重启 VPS。新内核已经安装，但重启应由用户另行确认。

## 7. 初始内容

上线时提供 3 篇可编辑示例文章，全部使用真实、可替换的站内内容：

1. 《我如何看一台 NAT 主机：从端口映射到可用边界》
2. 《十堰出发的线路观察：国内访问、海外依赖与实际延迟》
3. 《一次 apt/dpkg 卡死的恢复记录：为什么不要直接删锁文件》

封面使用一张本地生成的线路观察主题位图；后续文章可在后台上传替换。

## 8. 错误处理与安全边界

- 未登录访问后台统一返回登录页，不泄露文章草稿和媒体路径。
- 过期会话返回 401 并清理 cookie。
- 文章不存在返回自定义 404 页面，不把数据库异常暴露给访客。
- 上传限制单文件 5MB，只允许常见图片 MIME，并使用随机文件名。
- 登录失败采用统一提示，避免暴露用户名是否存在；记录最近失败时间但第一版不做复杂封禁。
- 公共 API 设置合理分页上限，避免一次请求拖垮 2GB 主机。
- SSH、Nginx 和应用日志分开，定期轮转。

## 9. 验收标准

### 功能

- 访客可以从首页打开文章、按标签筛选、搜索并阅读 Markdown 内容。
- 管理员可以登录、创建草稿、预览、发布、编辑、撤回和删除文章。
- 文章封面和媒体上传可用，非法文件被拒绝。
- 重启应用后文章、会话失效规则和媒体文件状态正确。

### 运维

- `systemctl status shiyan-blog` 为 active。
- Nginx 能从映射端口访问，应用不会直接暴露 `8000`。
- `sqlite3` 检查数据库完整性通过，备份文件可以复制并恢复。
- 通过 `curl` 验证首页、文章页、登录和健康检查接口。
- 移动端 390px 和桌面端 1440px 下无明显溢出、遮挡或不可点击控件。

### 约束

- 不安装 WordPress、Ghost 或大型管理面板。
- 不依赖海外字体、图片 CDN、Docker Hub 或外部数据库。
- 不改变现有 SSH 端口映射，不自动重启系统。
