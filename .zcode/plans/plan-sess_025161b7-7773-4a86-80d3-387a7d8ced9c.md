## 目标
把考研学习控制台前端 `main.tsx`(1722 行)按职责拆分为 hooks + views,纯结构重构,**对外行为完全不变**。不引新依赖、不动后端、不改 styles.css。

## 现状
- 已有独立模块且各自带单测:`api.ts / focusTimer.ts / focusNotify.ts / focusStats.ts / studyCore.ts / storage.ts / format.ts / uiComponents.tsx`
- 唯一职责混杂的是 `App` 组件:~30 个 useState、~20 个函数、5 个 useEffect、5 个 view 的完整内联 JSX
- 测试 `vitest run`,构建 `tsc && vite build`
- `frontend/scripts/verify_focus_sticky.mjs` 是有价值的 Playwright E2E 脚本(已读全文确认)→ 入库保留

## 实施步骤(每步 = 一次独立提交,每步跑 `npm test` + `npm run build`,全绿才进下一步)

### 阶段 0:绿基线 + 收 E2E 脚本
- 跑 `npm test`、`npm run build`,记录重构前基线
- `frontend/scripts/verify_focus_sticky.mjs` 加入版本控制
- 提交:`chore: track focus sticky e2e script and establish refactor baseline`

### 阶段 1:抽 hook(纯逻辑提取,不动 JSX)
新建 `src/hooks/`,把 `App` 的 state + useEffect + 函数按职责搬入 hook。`App` 改为调用 hook,render 暂不动。每抽一个 hook 配 `.test.ts`(优先测从 hook 下沉出的纯函数;副作用/渲染相关先用现有模块的测试覆盖,不强加 @testing-library)。

顺序(先低耦合后高耦合):
1. `useView.ts` — view/setView + saveView effect
2. `useSelectedDate.ts` — selectedDate/setSelectedDate
3. `useAppData.ts` — data/setData/updateData + 任务/科目/复盘/导入/重置等函数 + saveAppData effect
4. `useBackup.ts` — backupMeta/backupBannerDismissed/backupHealth/downloadData/downloadExportFile
5. `useApiCoach.ts` — health/apiForm/aiAdvice/aiStatus/各 loading flag + fetchConfig effect + askAiCoach/saveApiConfig/testApiConfig
6. `useFocusNotify.ts` — focusNotifyPrefs/focusNotifyStatus + updateFocusNotifyPrefs/requestNotificationPermissionFromSettings/testFocusNotify
7. `useFocusStats.ts` — focusStatsStore/focusStats/applyFocusSessionLog
8. `useWeeklyReport.ts` — weeklyReport/weeklyReportStatus + 生成/复制/下载/写入复盘
9. `usePlanActions.ts` — planScope/planFilters/planActionStatus + 计划页各 action 函数
10. `useFocusTimer.ts`(最复杂,最后做)— focusTimer/focusNow/pomodoroMinutes/focusStatusMessage/focusRestore/focusRestoreNotifiedRef + 1 秒 tick effect + 键盘快捷键 effect + begin/pause/finish/cancel/skipBreak/changeMode/changePomodoroMinutes;**保留 `focusActionRefs` ref 模式**(避免全局 keydown listener 闭包陈旧);与 useFocusStats/useAppData 的交互通过回调注入,不直接耦合

每个 hook 一次提交:`refactor: extract useXxx from App`

### 阶段 2:拆视图组件(搬 JSX)
新建 `src/views/`:`TodayView / PlanView / ProgressView / CoachView / SettingsView`,把对应 `{view === "xxx" && (...)}` 整段搬入,props 传入所需 hook 数据与回调。
公共顶部 banners(StorageWarning / BackupBanner / OverdueBanner)、HeroBand、Tabs 抽到 `src/components/`(与已有 `uiComponents.tsx` 并列;uiComponents 保持偏原子组件)。
`App` 退化为「组合各 hook + 选 view 渲染」薄壳,目标 ≤ 250 行。
每拆一个 view 一次提交:`refactor: split XxxView from App`

### 阶段 3:验证与收尾
- 全量跑 `npm test` + `npm run build`
- 可选:运行 `verify_focus_sticky.mjs`(需本地起 dev server + playwright,环境不便则跳过并注明)
- `git status` 确认只剩本次重构文件,无意外散落改动
- 分批提交按每步粒度完成

## 不会做
- 不改后端、不引新依赖、不动 styles.css
- 不改对外功能与持久化格式;sessionStorage/localStorage key 一律不变
- 不动现有模块的对外签名(只在必要时往里加导出供 hook/测试用)
- 不提交 git 内容(仅改工作区文件,何时 commit 由你决定;每步完成后我会提示)

## 风险与回滚
- 每步独立,任一步出问题可单独 revert
- 关键风险点:`useFocusTimer` 的 1 秒 tick 与键盘 effect 依赖数组、`focusActionRefs` 闭包、`useAppData` 与 focus 的双向回调注入;这些会在该步放慢、先对齐签名再迁移
